Where do the messages end up?

Cloudflare Worker → Email/Slack Recommended

Tiny endpoint you own. Forwards to your inbox, a Slack channel, or a Discord webhook.

  • Free tier: 100 000 requests/day
  • Server-side IP rate limiting & spam filtering
  • No vendor branding in messages
  • You keep the secrets off the client
Cost: $0 · Setup: ~30 min

GitHub Issues (private repo) Great for triage

Worker calls the GitHub API and creates an issue in a private feedback repo. You get labels, threading, and can turn any message into a real bug.

  • Free, no extra infra beyond the Worker
  • Uses labels: feedback, bug, idea
  • You already use GitHub for releases
Cost: $0 · Setup: ~45 min

Formspree / Web3Forms Zero backend

Managed form service. Frontend POSTs directly, they email you.

  • No code on your side beyond the fetch call
  • Free tier: 50 submissions/mo (Formspree)
  • Vendor dependency, less control over anti-spam
Cost: $0 → $10/mo · Setup: ~10 min

Website inbox page Later

If you want a public "roadmap-style" view, mirror GitHub Issues onto a small Next.js page (e.g. agentrium.app/feedback).

  • Users see status of their reports
  • Doubles as social proof
  • Only worth it once volume justifies it
Cost: $0 (Vercel) · Setup: half a day

Anti-spam layers baked into the sketch

  • Honeypot field - hidden website input; if it's filled, silently drop. Catches ~90% of naive bots.
  • App-signed request - a build-embedded token proves the message came from a real Agentrium install (not a public web scraper). Not a real secret, but raises the bar.
  • Server-side IP rate limit - Worker rejects >5 messages/hour per IP.
  • Length caps - maxlength on both fields; server re-validates.
  • No email field - nothing to harvest, so this form is uninteresting to scrapers.
